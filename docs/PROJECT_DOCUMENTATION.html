1. Executive Summary & Overview

Hamro Pasal (Nepali for "Our Shop") is a high-performance, full-stack e-commerce application designed to provide a secure, fast, and feature-rich shopping experience. The project was built from scratch, transitioning from a basic monorepo setup to a multi-container Dockerized production environment.

Key features include a secure double-token (Access + Refresh) authentication system, dynamic filtering on the product catalog, a persistent shopping cart and wishlist, coupon promo codes, authenticated user ratings/reviews, dynamic collaborative-category recommendations, administrative dashboards, local invoice PDF rendering, and multiple payment gateway integrations (Stripe, eSewa, and IME Pay).

2. Technical Stack & Architecture

The application is architected as a monorepo consisting of:

  • Backend: Built using NestJS (TypeScript), structured into clean, modular features. It relies on Passport and JWT for authentication, Helmet for security headers, rate-limiting guards, and Prisma ORM to interact with the database.
  • Frontend: React single-page application (SPA) bundled with Vite. State management is handled with Zustand (with localStorage persistence for the cart/wishlist), styled with modular vanilla CSS (supporting Dark/Light mode theme configurations), and lazy-loaded routing.
  • Database: SQLite connected via Prisma ORM. During database transactions, atomic locks are used to preserve consistency.
  • DevOps & Infrastructure: Dockerized with two isolated services (Backend NestJS server and Frontend static Nginx container) orchestrated through Docker Compose.

4. Database Schema Structure

The prisma schema details models representing the core components of Hamro Pasal: 

model User {
  id        String   @id @default(uuid())
  email     String   @unique
  password  String
  name      String?
  role      String   @default("USER")
  hashedRt  String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  orders    Order[]
  reviews   Review[]
}

model Product {
  id          String      @id @default(uuid())
  title       String
  description String
  price       Float
  image       String
  category    String
  stock       Int
  createdAt   DateTime    @default(now())
  updatedAt   DateTime    @updatedAt
  orderItems  OrderItem[]
  reviews     Review[]
}

model Order {
  id                 String      @id @default(uuid())
  userId             String
  status             String      @default("PENDING") // PENDING, PROCESSING, SHIPPED, DELIVERED, CANCELLED
  totalAmount        Float
  discountAmount     Float       @default(0)
  couponId           String?
  paymentMethod      String      @default("STRIPE") // STRIPE, ESEWA, IME_PAY
  paymentId          String?
  shippingAddress    String
  shippingCity       String
  shippingPostalCode String
  shippingCountry    String
  createdAt          DateTime    @default(now())
  updatedAt          DateTime    @updatedAt
  user               User        @relation(fields: [userId], references: [id], onDelete: Cascade)
  coupon             Coupon?     @relation(fields: [couponId], references: [id])
  items              OrderItem[]
}

model OrderItem {
  id        String   @id @default(uuid())
  orderId   String
  productId String
  quantity  Int
  price     Float    // Historical price snapshot
  order     Order    @relation(fields: [orderId], references: [id], onDelete: Cascade)
  product   Product  @relation(fields: [productId], references: [id])
}

model Review {
  id        String   @id @default(uuid())
  rating    Int
  comment   String
  userId    String
  productId String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  product   Product  @relation(fields: [productId], references: [id], onDelete: Cascade)
}

model Coupon {
  id             String      @id @default(uuid())
  code           String      @unique
  discountType   String      // PERCENTAGE, FIXED
  value          Float
  minOrderAmount Float       @default(0)
  maxUses        Int?
  usedCount      Int         @default(0)
  active         Boolean     @default(true)
  expiresAt      DateTime?
  createdAt      DateTime    @default(now())
  updatedAt      DateTime    @updatedAt
  orders         Order[]
}

5. Payment Gateways Sandbox Integrations

Hamro Pasal provides checkout support for three gateways.

Gateway Type Verification Process
Stripe Global Cards Stripe Elements client-side payment tokens, verified via Stripe API payment intents on the backend.
eSewa Nepali Wallet Client is redirected to the eSewa Sandbox. On success, the backend processes callbacks and validates transaction details cryptographically.
IME Pay Nepali Wallet Client is redirected to IME Pay portal, and on return, payment verification queries are dispatched to confirm success status.

6. Deployment & Run Instructions

Running via Docker Compose (Recommended)

Deploy the entire environment with a single command: 

# Start all services and run database migrations/seeding automatically
docker compose up --build -d

Checking Log Output

# Check Docker Compose logs
docker compose logs -f

Running Locally (Development Mode)

To run services independently: 

# 1. Start SQLite database and migrations in backend/
cd backend
npm install
npx prisma migrate dev
npm run start:dev

# 2. Run React development server in frontend/
cd ../frontend
npm install
npm run dev
